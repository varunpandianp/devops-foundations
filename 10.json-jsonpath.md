# JSON, YAML, JSONPath and JSON Query Language — DevOps Fundamentals

## 1. What Is JSON?

JSON stands for **JavaScript Object Notation**. It is a lightweight data format used to store, exchange, and transfer structured data between applications.

In DevOps, JSON is commonly used in:

- AWS CLI responses and configuration.
- REST APIs.
- Application configuration files.
- Infrastructure automation.
- Kubernetes API responses.
- Cloud monitoring and logging systems.

Example:

```json
{
  "name": "John",
  "gender": "male",
  "age": 24
}
```

Here, `name`, `gender`, and `age` are keys, and `"John"`, `"male"`, and `24` are their values.

## 2. JSON Data Types

JSON supports six basic value types.

### String

Text enclosed in double quotes.

```json
{
  "name": "John"
}
```

### Number

Numbers can be integers or decimals.

```json
{
  "age": 24,
  "salary": 45000.50
}
```

### Boolean

```json
{
  "active": true,
  "admin": false
}
```

### Null

Represents the absence of a value.

```json
{
  "middle_name": null
}
```

### Object (Dictionary)

An object contains key-value pairs.

```json
{
  "employee": {
    "name": "John",
    "age": 24
  }
}
```

### Array (List)

An array contains an ordered sequence of values.

```json
{
  "tools": [
    "Git",
    "Docker",
    "Kubernetes"
  ]
}
```

An array can also contain multiple objects:

```json
{
  "employees": [
    {
      "name": "John",
      "age": 24
    },
    {
      "name": "Sarah",
      "age": 28
    }
  ]
}
```

## 3. JSON Object vs Array

| Feature | Object | Array |
|---|---|---|
| Also called | Dictionary or mapping | List or sequence |
| Syntax | `{}` | `[]` |
| Access method | Key | Index or query |
| Example | `{"name": "John"}` | `["John", "Sarah"]` |
| Common purpose | Describe one entity | Store multiple values or records |

Example:

```json
{
  "employee": {
    "name": "John",
    "age": 24
  }
}
```

Here, `employee` is a key whose value is an object.

To store multiple employees:

```json
{
  "employee": [
    {
      "name": "John",
      "age": 24
    },
    {
      "name": "Sarah",
      "age": 28
    }
  ]
}
```

Now `employee` is a key whose value is an array of objects.

**Remember:** The key itself does not determine whether something is a dictionary or list. Its value's structure does.

## 4. Accessing JSON Data

Consider this JSON document:

```json
{
  "company": "TechCorp",
  "employees": [
    {
      "name": "John",
      "age": 24,
      "department": "DevOps"
    },
    {
      "name": "Sarah",
      "age": 28,
      "department": "Cloud"
    },
    {
      "name": "David",
      "age": 32,
      "department": "SRE"
    }
  ]
}
```

### Access the company

```text
company
```

Value:

```text
TechCorp
```

### Access the employees array

```text
employees
```

### Access the first employee

Array indexes usually start at `0`.

```text
employees[0]
```

Result:

```json
{
  "name": "John",
  "age": 24,
  "department": "DevOps"
}
```

### Access the first employee's name

```text
employees[0].name
```

Result:

```text
John
```

### Access the second employee's age

```text
employees[1].age
```

Result:

```text
28
```

### Access the third employee's department

```text
employees[2].department
```

Result:

```text
SRE
```

These examples describe the navigation concept. The exact expression depends on the query language being used.

## 5. What Is JSONPath?

**JSONPath** is a query syntax for navigating and selecting data from JSON documents.

It allows you to access nested objects, select array elements, and filter arrays using criteria.

Common uses include:

- Retrieving a particular field.
- Accessing nested dictionaries.
- Selecting an array element by index.
- Finding records that match a condition.
- Extracting specific values from complex JSON responses.

### Important JSONPath symbols

| Symbol | Meaning |
|---|---|
| `$` | Root of the JSON document |
| `.` | Access a child property |
| `[]` | Array index or selector |
| `[*]` | All items in an array |
| `?()` | Filter expression |
| `@` | Current item being evaluated |
| `..` | Recursive descent into nested data |
| `*` | Wildcard for matching children |
| `==` | Equality comparison |
| `!=` | Not equal |
| `>` | Greater than |
| `<` | Less than |
| `>=` | Greater than or equal |
| `<=` | Less than or equal |

JSONPath implementations can differ in the filters and operators they support. Use the syntax supported by your particular tool.

## 6. JSONPath Root and Property Access

Using the company JSON example:

### Root object

```text
$
```

Selects the entire JSON document.

### Company name

```text
$.company
```

### Employees array

```text
$.employees
```

### First employee object

```text
$.employees[0]
```

### First employee's name

```text
$.employees[0].name
```

### Second employee's department

```text
$.employees[1].department
```

### All employee names

```text
$.employees[*].name
```

Expected values:

```json
[
  "John",
  "Sarah",
  "David"
]
```

### All employee ages

```text
$.employees[*].age
```

Expected values:

```json
[
  24,
  28,
  32
]
```

## 7. JSONPath Filtering — Most Important Topic

Filtering lets you search an array of objects based on a condition.

The general pattern is:

```text
$.array_name[?(@.property operator value)]
```

Explanation:

- `$` starts at the root.
- `.array_name` selects the array.
- `[?()]` filters its elements.
- `@` represents the current element.
- `.property` selects a property of that element.
- The operator compares the property with a value.

### Example 1: Employees older than 25

```text
$.employees[?(@.age > 25)]
```

Expected matches: Sarah and David.

### Example 2: Employees younger than 30

```text
$.employees[?(@.age < 30)]
```

Expected matches: John and Sarah.

### Example 3: Employees aged exactly 28

```text
$.employees[?(@.age == 28)]
```

Expected match: Sarah.

### Example 4: Employees not aged 24

```text
$.employees[?(@.age != 24)]
```

Expected matches: Sarah and David.

### Example 5: Employees in the DevOps department

```text
$.employees[?(@.department == 'DevOps')]
```

Expected match: John.

### Example 6: Employees aged 28 or above

```text
$.employees[?(@.age >= 28)]
```

Expected matches: Sarah and David.

**Remember this pattern:**

```text
$[?(@.property > value)]
```

This shorter form applies when the root JSON value itself is an array.

For the earlier example, the root is an object, so you must navigate to the array first:

```text
$.employees[?(@.age > 25)]
```

## 8. Filtering When the Root Is an Array

Suppose the JSON data itself is an array:

```json
[
  {
    "name": "John",
    "age": 24
  },
  {
    "name": "Sarah",
    "age": 28
  },
  {
    "name": "David",
    "age": 32
  }
]
```

Now the JSONPath expressions are:

### Find people older than 25

```text
$[?(@.age > 25)]
```

### Find people named Sarah

```text
$[?(@.name == 'Sarah')]
```

### Find people aged 24

```text
$[?(@.age == 24)]
```

### Find people younger than 30

```text
$[?(@.age < 30)]
```

The distinction is important:

- `$.employees[?(@.age > 25)]` — the root is an object containing an `employees` array.
- `$[?(@.age > 25)]` — the root itself is an array.

## 9. Search Nested JSON Data

Consider:

```json
{
  "employee": {
    "name": "John",
    "address": {
      "city": "Edison",
      "state": "New Jersey",
      "country": "United States"
    }
  }
}
```

### Access the employee's name

```text
$.employee.name
```

### Access the city

```text
$.employee.address.city
```

### Access the state

```text
$.employee.address.state
```

### Access the country

```text
$.employee.address.country
```

### Recursive descent

```text
$..city
```

This searches recursively for properties named `city` in the JSON document, wherever they occur.

Recursive descent is useful when the nesting level is not known in advance.

## 10. More Advanced JSONPath Filters

### Filter by a string

```text
$.employees[?(@.department == 'Cloud')]
```

### Filter by a numeric range

```text
$.employees[?(@.age >= 25 && @.age <= 30)]
```

This example uses logical AND (`&&`) in implementations that support it.

### Filter by multiple criteria

```text
$.employees[?(@.age > 25 && @.department == 'Cloud')]
```

This searches for employees who are older than 25 and belong to Cloud.

### Logical OR

```text
$.employees[?(@.department == 'Cloud' || @.department == 'SRE')]
```

This searches for employees whose department is Cloud or SRE, where the implementation supports `||`.

### Select only a field after filtering

```text
$.employees[?(@.age > 25)].name
```

Expected values:

```json
[
  "Sarah",
  "David"
]
```

### Search for a missing property

Some JSONPath implementations support filters such as:

```text
$.employees[?(!@.department)]
```

However, missing properties, `null` values, and Boolean expressions can behave differently across implementations. Check the implementation's documentation before relying on this syntax.

## 11. What Is JMESPath?

**JMESPath** is a JSON query language used to extract and filter data from JSON documents.

It is especially useful in the AWS CLI because AWS CLI supports JMESPath expressions through the `--query` option.

Although JSONPath and JMESPath have similar goals, their syntax is different.

### Access a property

JSONPath:

```text
$.company
```

JMESPath:

```text
company
```

### Access the first employee's name

JSONPath:

```text
$.employees[0].name
```

JMESPath:

```text
employees[0].name
```

### Get every employee's name

JSONPath:

```text
$.employees[*].name
```

JMESPath:

```text
employees[*].name
```

### Filter employees older than 25

JSONPath:

```text
$.employees[?(@.age > 25)]
```

JMESPath:

```text
employees[?age > `25`]
```

In JMESPath, backticks are used here to represent the JSON numeric literal `25`.

### Return only the names of employees older than 25

JSONPath:

```text
$.employees[?(@.age > 25)].name
```

JMESPath:

```text
employees[?age > `25`].name
```

### Filter by department

JMESPath:

```text
employees[?department == 'Cloud']
```

The exact output shape can differ between JSONPath implementations and JMESPath, particularly when extracting properties after filtering.

## 12. JSONPath vs JMESPath vs jq

| Feature | JSONPath | JMESPath | jq |
|---|---|---|---|
| Main purpose | Navigate and filter JSON | Query and transform JSON data | Query and transform JSON data |
| Typical syntax | `$.employees[0].name` | `employees[0].name` | `.employees[0].name` |
| Filtering example | `$.employees[?(@.age > 25)]` | `employees[?age > \`25\`]` | `.employees[] \| select(.age > 25)` |
| AWS CLI | Not the standard `--query` language | Supported by `--query` | Can be used separately |
| Common use | JSON data navigation | Cloud/API data extraction | Shell-based JSON processing |

`jq` is a command-line JSON processor. Its pipe operator (`|`) passes one result to the next operation.

Example:

```bash
jq '.employees[] | select(.age > 25) | .name' employees.json
```

Expected output:

```text
"Sarah"
"David"
```

## 13. YAML vs JSON

YAML and JSON are both used to represent structured data.

### YAML example

```yaml
employee:
  name: John
  age: 24
  tools:
    - Git
    - Docker
    - Kubernetes
```

### Equivalent JSON

```json
{
  "employee": {
    "name": "John",
    "age": 24,
    "tools": [
      "Git",
      "Docker",
      "Kubernetes"
    ]
  }
}
```

### Main differences

| Feature | YAML | JSON |
|---|---|---|
| Objects | Indented key-value pairs | `{}` |
| Arrays | Items beginning with `-` | `[]` |
| Strings | Often unquoted when unambiguous | Double-quoted |
| Comments | Supported using `#` | Not supported in standard JSON |
| Common DevOps use | Docker Compose, Kubernetes, Ansible, workflows | API responses, AWS data, application data |

YAML and JSON can represent similar data structures, but they are not interchangeable in every context. The target tool determines which format is accepted.

## 14. Working with JSON in the Linux Terminal

Create a file:

```bash
vi employees.json
```

Add:

```json
{
  "employees": [
    {
      "name": "John",
      "age": 24
    },
    {
      "name": "Sarah",
      "age": 28
    }
  ]
}
```

### Display JSON

```bash
cat employees.json
```

### Validate and format JSON

```bash
python -m json.tool employees.json
```

This validates standard JSON syntax and prints a formatted version.

### Extract values using jq

```bash
jq '.employees[0].name' employees.json
```

### Extract all employee names

```bash
jq '.employees[].name' employees.json
```

### Filter employees older than 25

```bash
jq '.employees[] | select(.age > 25)' employees.json
```

### Filter and return names only

```bash
jq '.employees[] | select(.age > 25) | .name' employees.json
```

Install `jq` using your Linux distribution's package manager if it is not already available.

## 15. JSONPath in Kubernetes

Kubernetes supports its own JSONPath-based output expressions through `kubectl`.

Example:

```bash
kubectl get pods -o jsonpath='{.items[*].metadata.name}'
```

This prints the names of the Pods.

### Get Pod names and their node names

```bash
kubectl get pods -o jsonpath='{range .items[*]}{.metadata.name}{" "}{.spec.nodeName}{"\n"}{end}'
```

### Get container images

```bash
kubectl get pods -o jsonpath='{.items[*].spec.containers[*].image}'
```

**Important:** Kubernetes `kubectl` JSONPath syntax is not identical to every general-purpose JSONPath implementation. For example, the filtering syntax in Kubernetes should not be assumed to support every operator available in other JSONPath libraries.

## 16. JSON Queries in AWS CLI

AWS CLI's `--query` option uses JMESPath, not standard JSONPath.

### Get EC2 instance IDs

```bash
aws ec2 describe-instances \
  --query 'Reservations[*].Instances[*].InstanceId' \
  --output json
```

### Get instance IDs and states

```bash
aws ec2 describe-instances \
  --query 'Reservations[*].Instances[*].[InstanceId,State.Name]' \
  --output table
```

### Filter running EC2 instances

```bash
aws ec2 describe-instances \
  --query 'Reservations[*].Instances[?State.Name==`running`].InstanceId' \
  --output json
```

### Get S3 bucket names

```bash
aws s3api list-buckets \
  --query 'Buckets[*].Name' \
  --output json
```

These examples require the AWS CLI to be configured and the corresponding IAM permissions to be available.

## 17. Common Mistakes

### Mistake 1: Confusing JSONPath and JMESPath

JSONPath:

```text
$.employees[?(@.age > 25)]
```

JMESPath:

```text
employees[?age > `25`]
```

They are not the same syntax.

### Mistake 2: Forgetting the root structure

If JSON starts with an object:

```json
{
  "employees": []
}
```

Use:

```text
$.employees
```

If JSON starts directly with an array:

```json
[
  {"name": "John"}
]
```

Use a root-array expression such as:

```text
$[0].name
```

### Mistake 3: Using the wrong index

Array indexing starts at zero:

```text
$.employees[0]
```

Selects the first employee, not the second.

### Mistake 4: Using the wrong value type

For a JSON numeric value:

```json
{"age": 28}
```

Use a numeric comparison:

```text
$.employees[?(@.age > 25)]
```

Do not assume a quoted string such as `"28"` behaves the same as the number `28`.

### Mistake 5: Expecting every tool to support every JSONPath expression

A valid expression in one JSONPath library may not work in Kubernetes or another tool. Always check the target tool's query syntax.

### Recommended learning order

1. Understand JSON objects, arrays, keys, and values.
2. Practise accessing nested properties and array indexes.
3. Learn JSONPath filters using `?()` and `@`.
4. Learn JMESPath because of its importance in AWS CLI.
5. Practise `jq` for Linux shell scripting.
6. Practise Kubernetes JSONPath with `kubectl get`.
7. Use these skills to inspect AWS API responses, automate cloud tasks, and troubleshoot infrastructure.

**Key takeaway:** JSON is the data format; JSONPath, JMESPath, and jq are different ways to navigate, query, or transform that data. YAML is another data-serialization format commonly used to configure DevOps tools.
